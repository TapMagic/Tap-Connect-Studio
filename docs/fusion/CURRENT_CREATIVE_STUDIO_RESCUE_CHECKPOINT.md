## Owner Review Findings

The Replit result is not Owner-ready.

The public landing page has:

- strong product architecture and substantial copy
- weak composition and page rhythm
- hero clipping
- orbit geometry constrained by the wrong frame
- overlapping labels
- Card partially obscured by panels
- repeated map/explorer explanations
- product imagery that appears blank or too dark
- semantic colors that remain too subtle
- an overly editorial rather than premium product feel

The Home dashboard has:

- useful Card-centered concepts
- useful proof, attention and next-action concepts
- weak prioritization
- no strong visible living Card at the center
- duplicated attention surfaces
- placeholder/scaffolding language
- raw technical errors displayed to the Owner
- too much information presented simultaneously
- weak mobile hierarchy

The Card editor contains substantial capability, but:

- it is cumbersome
- terminology is ambiguous
- the canvas does not dominate
- navigation and workspace chrome consume too much space
- selecting objects primarily depends on menus/Outline
- clicking a Card button currently activates its customer action
- the top workspace area does not clearly collapse or recede
- contextual tools change, but the room does not sufficiently rearrange around the task
- Undo/Redo may technically exist but are not obvious enough to be understood
- font controls are severely underpowered
- current size controls use Small/Medium/Large/2X/3X rather than professional point sizing
- the font library is not a full professional catalog
- fonts are not consistently previewed in their actual appearance
- desktop/tablet/phone simulations exist, but there is no strong real-device QR draft-preview experience

## Locked Product Law

The Card is the center of TapConnect.

TapConnect is the living Card.

TapConnect Studio is the system working around the Card to:

- create it
- connect customers to it
- keep the relationship
- operate the relationship
- prove what the Card accomplished

Do not create a competing center.

## Locked Creative-Studio Law

Do not simplify the product.

Simplify the user’s current moment.

The desired authoring model is:

- **ONE DOMINANT CANVAS**
- **ONE COMPACT TOOL RAIL**
- **ONE CONTEXTUAL PANEL STACK**
- **ONE PERSISTENT SAFETY / ACTION BAR**

Unused chrome must return space to the Card.

Complexity remains available through progressive disclosure.

Panels may contain subpanels.

Example:

Button  
→ Typography  
→ Font  
→ Font family selection

or:

Button  
→ Appearance  
→ Fill  
→ Brand colors / Recent / Custom

The deeper the Owner travels, the narrower the question becomes.

Do not make deeper navigation display more unrelated controls.

## Locked Edit / Preview / Public Contract

### Edit Mode

- clicking an object selects it
- clicking a customer-facing button does not activate it
- clicking Website does not leave the editor
- clicking Directions does not open Maps
- clicking phone/email does not activate the action
- selected object receives a clear editing treatment
- corresponding contextual panel opens
- Outline synchronizes with canvas selection
- Undo/Redo remain visible
- Save state remains visible

> **Locked law: EDIT SELECTS.**

### Preview Mode

- customer-facing actions work safely
- editor outlines disappear
- contextual controls recede
- Desktop, Tablet and Phone simulations are available
- a real-device preview is available
- preview is clearly marked as test/draft
- exiting Preview restores the editing state and selection

> **Locked law: PREVIEW ACTIVATES.**

### Public Mode

- uses the actual published Card
- contains published content only
- uses the permanent public URL
- remains distinct from draft Preview

> **Locked law: PUBLIC BEHaves live.**

## Locked Panel Model

The canvas is the primary selection method.

Examples:

- select headline → Text panel
- select logo → Logo/Image panel
- select button → Button panel
- select offer → Spotlight panel
- select TapSave → TapSave panel
- select background → Card Appearance panel
- select section → Section/Layout panel

Outline remains the structural backup for:

- reorder
- nested elements
- overlapping elements
- hidden elements
- small targets
- accessibility labels
- long Cards

Every panel level must provide:

- clear title
- parent context
- Back one level
- Close panel
- predictable focus
- no lost changes
- useful panel memory
- accessible keyboard/touch behavior

Desktop:

- sliding/resizable right inspector
- collapsible to an edge tab
- canvas remains dominant

Tablet:

- overlay or partial-width panel
- no permanent canvas compression

Phone:

- bottom sheet for common controls
- full-screen panel for deep controls
- clear Back
- one-tap return to canvas

## Locked Workspace Behavior

The top workspace area and navigation must support:

- Expanded
- Compact / Peek
- Collapsed
- Pinned
- Focus mode

The Owner must be able to collapse and reopen them manually.

The system may intelligently recede during focused editing, but reopening must be obvious.

Even when collapsed, preserve:

- Back to Card overview
- Card name
- saved/unsaved state
- Undo
- Redo
- Preview as customer
- Save
- Finish editing

Undo and Redo are permanent safety controls, not hidden tool functions.

They must include:

- recognizable icons
- visible tooltip
- accessible labels
- disabled state
- keyboard shortcuts
- human-readable history where practical

## Locked Professional Typography Requirements

The current font system is inadequate.

Do not deliver a watered-down free word processor.

Install or integrate a production-grade, appropriately licensed open-source font catalog.

Target:

- at least 50–75 well-selected families initially
- extensible to hundreds
- lazy loading
- no loading every font and weight at startup
- accurate weight and italic availability
- Brand fonts preloaded
- recent fonts
- favorites
- search
- categories
- useful recommendations
- real font previews rendered in each actual family

Categories should include:

- Sans Serif
- Serif
- Display
- Slab Serif
- Humanist
- Geometric
- Handwriting / Script
- Monospace
- Condensed
- Editorial
- Friendly / Rounded
- High-impact headline

The font picker must show:

- font name
- sample rendered in that font
- current font
- available styles where useful
- favorites
- Brand-approved status

Provide a font viewing window with:

- selected Card text
- custom sample
- alphabet
- numbers
- punctuation
- uppercase/lowercase
- headline sample
- paragraph sample

Replace preset-only Small/Medium/Large/2X/3X sizing with real numeric point control.

Provide:

- direct numeric input
- point values
- increment/decrement
- optional slider
- keyboard adjustment
- sensible ranges
- optional presets as shortcuts only

Professional typography controls must include:

- font family
- exact point size
- available numeric weights
- bold
- italic
- underline
- strikethrough where appropriate
- left/center/right alignment
- justified text where appropriate
- line height
- letter spacing
- capitalization/case
- paragraph spacing
- text width
- wrapping
- responsive behavior
- text color
- automatic accessible contrast
- Brand inheritance
- Reset to Brand
- explicit local override

Do not pretend a font provides weights or italics that do not exist.

## Locked Preview and QR Requirements

Preview toolbar:

- Desktop
- Tablet
- Phone
- Live device
- Refresh preview
- Copy preview link
- Open in new tab
- Exit preview

Desktop/Tablet/Phone are simulations.

Live Device is the real-device truth.

Create a secure temporary QR draft-preview system.

The QR must open the current working Card draft on a real phone without requiring Studio login and without publishing the Card.

The preview must use:

- unguessable signed token
- Business/Card scoping
- expiry
- revocation
- no Clerk session exposure
- no admin mutation
- no permanent public slug
- minimal safe telemetry
- no cross-tenant leakage

The live phone preview must clearly identify:

- Card name
- Preview/Test
- current working or saved draft
- last updated time
- not published status

The QR-generated phone preview should support safe customer behavior:

- Website
- Directions/Maps
- phone
- email
- Save Contact
- copy link
- ordinary safe external URLs

Provider-dependent or consequential behavior must remain safe:

- no live payment
- no live Campaign send
- no customer contact
- no production workflow
- no false success

When editing directly on a phone, replace QR-first behavior with:

- Open customer preview
- Return to editing
- Copy preview link
- Share preview

## Green Action Law

Green means meaningful forward action.

Use green for:

- Save
- Continue
- Publish
- Update preview
- Apply consequential change
- clear forward action

Do not use green merely because:

- a tool is selected
- a panel is open
- an item is active
- a Card name is displayed
- an Outline row is selected

Use neutral or Card-semantic selection treatments instead.
